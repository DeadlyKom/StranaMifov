# Перемещение шестибайтовых объектов

Статический разбор `head.co:#92CB..#9449`, проверок кандидатов и переноса записи.

```text
ПЕРЕМЕЩЕНИЕ ШЕСТИБАЙТОВЫХ ОБЪЕКТОВ, HEAD #92CB..#9449

Источник списка
  #6B69, четыре записи по 4 байта, указатель и 16-битное количество
  #7A74 выбирает запись текущего континента, содержимое списка в банке 0
  Объект имеет шаг 6 байтов, +0 флаги, +1 x, +2 y, +3 ID описателя

Отбор записи
  бит 0 установлен -> следующая запись
  вне включительного прямоугольника герой ±3 -> следующая запись
  прямоугольник ограничен x=0..160, y=0..99
  ((flags AND #20) ROL 3) != (#6A33 AND 3) -> следующая запись
  режим полёта 2 не совпадает ни с одним значением одного бита 0/1
  координаты совпадают с героем -> следующая запись

Выбор трёх кандидатов
  #7C71 вычисляет направление от объекта к герою
  #9245 с таблицей #92A4 формирует до трёх соседних координат
  candidate x <3 либо >=158 -> следующий кандидат
  candidate y <3 либо >=97 -> следующий кандидат
  flags.bit5=0 и класс клетки=#FF -> следующий кандидат
  flags.bit5=1 и класс клетки!=#FF -> следующий кандидат

Проверка занятости, результат C подпрограммы #8CD1
  C=0 -> #80C4 читает карту, установленный бит 7 запрещает кандидат
  C=8 -> SET 0,(IX+0) у найденного объекта, RES 0,(HL) у его байта карты
         применяется бит 0, а не бит 7, это сохранённый код оригинала
  остальные C -> следующий кандидат

Проверка способностей
  класс клетки=0 -> перенос разрешён без проверки описателя
  класс клетки!=0 -> #7AEF для ID из +3, E AND класс должно быть ненулевым
  несовпадение -> следующий кандидат, использованная находка не восстанавливается

Перенос
  снимает бит 7 исходной клетки карты
  записывает x/y в +1/+2 исходной записи
  #91BF обновляет ориентацию по ранее сохранённому направлению
  ставит бит 7 новой клетки карты
  остальные кандидаты для этой записи больше не проверяются

Завершение
  после отказа всех трёх кандидатов координаты сохраняются
  IX +=6, число оставшихся записей BC уменьшается до 0
  исходная особенность указателя, #8CD1 меняет IX на найденную запись
  C!=0 и C!=8 ведёт #93BC -> #9432 без восстановления исходного IX
  если это последний кандидат, #943E прибавляет 6 уже к чужому указателю
  на успешном пути #9400 и перед проверкой способностей #93EB IX восстанавливается
  проявление этой особенности в игре не проверено
  непосредственного запуска боя в этой процедуре нет
  игровое название списка по одному этому обработчику не устанавливается
  таблица описывает статические условия, запуск полной игры не выполнялся
```
